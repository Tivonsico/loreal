# v0.2 业务数据工作簿契约

本文档固定比赛工作簿的导入边界。导入器只读取下列七张业务表；`数据说明` 仅供人阅读。

## 固定规模与主键

| Sheet | 预期行数 | 幂等主键 |
|---|---:|---|
| 聊天记录 | 998 | `message_id`（同时校验 `会话ID + 消息序号` 唯一） |
| 订单 | 113 | `订单号` |
| 补发换货工单 | 24 | `工单号` |
| 线下打款工单 | 13 | `工单号` |
| 物流工单 | 15 | `工单号` |
| 不良反应工单 | 10 | `工单号` |
| 售后退货工单 | 18 | `工单号` |

所有编号都按字符串读取，禁止转成数字，以免丢失前导零。

## 表头

- 聊天记录：会话ID、消息序号、message_id、发送时间、角色、买家昵称、发送方、店铺、scene_major、scene_minor、is_target_buyer_message、message_text、内容类型、chat_content、category、image_path、关联订单号、关联工单号。
- 订单：订单号、会话ID、买家昵称、店铺、商品货号、商品名称、数量、单价(元)、实付金额(元)、订单状态、下单时间、付款时间、发货时间、快递公司、物流单号、收货省、收货市、赠品、买家留言。
- 补发换货工单：工单号、会话ID、关联订单号、买家昵称、店铺、工单类型、售后原因、发出商品货号、发出商品名称、数量、原订单物流单号、补发物流单号、快递公司、发货仓库、客诉加急、工单状态、处理人、创建时间、完成时间。
- 线下打款工单：工单号、会话ID、关联订单号、买家昵称、店铺、打款类型、退款问题类型、退款金额(元)、支付宝实名、支付宝账号、相关物流单号、转账状态、工单状态、处理人、创建时间、完成时间。
- 物流工单：工单号、会话ID、关联订单号、买家昵称、店铺、问题类型、快递公司、问题包裹物流单号、发货仓、订单实付(元)、处理方案、收货省、收货市、工单状态、处理人、创建时间、完成时间。
- 不良反应工单：工单号、会话ID、关联订单号、买家昵称、店铺、类型、年龄、肤质、使用商品、产品批次号、不适部位、症状描述、用后多久出现、是否停用、是否就医、任务状态、处理人、创建时间、完成时间。
- 售后退货工单：工单号、会话ID、关联订单号、买家昵称、店铺、包裹类型、退货原因、退货物流单号、快递公司、退款编号、签收建议、是否异常、任务状态、处理人、创建时间、完成时间。

## 规范化规则

- 角色：`买家 → customer`，`客服 → customer_service`，`系统推送 → system`。`system` 只允许历史导入和读取，浏览器不能以该角色发送消息。
- 消息正文：`message_text` 写入可检索的 `messages.content`；完整 `chat_content` 写入 `raw_content`。
- 时间：Excel 日期与日期字符串都转为同一时区的 datetime。付款时间末尾的 `（定金）` 先剥离，时间写入 `paid_at`，阶段写入 `payment_stage=deposit`。
- 状态：原中文状态保存在 `source_status`；工单管理状态统一映射为 `pending / processing / completed`。
- 关联：会话可无订单或工单；非空时必须引用已导入记录。同一会话最多一个订单、一个工单。昵称跨表不一致时阻止提交。
- 补发物流：原订单物流单号与补发物流单号分别保存，不可混用。
- 线下打款物流：仅退运费或售后期关闭等退货类记录允许填写相关物流单号。
- 不良反应：只保存工作簿中的脱敏登记；不得上传病历原件或额外身份信息。

## 导入事务

上传先生成预览，不写业务表。只有预览无错误时才能提交；提交以一个事务写入全部业务数据。重复提交同一文件按上述主键更新，不增加记录，也不为 998 条历史消息逐条产生实时广播。

## 客户侧公开字段

8000 端仅允许返回工单号、公开类型、统一状态、更新时间，以及已经确认的补发物流或退款结果。处理人、内部描述/备注、支付宝信息、风控标记、不良反应详情和导入原始字段一律不公开。
